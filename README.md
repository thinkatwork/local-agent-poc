# Local Research Assistant POC

A small local AI agent with a browser-based chat UI. It uses Ollama for inference on your Mac. It can search or read `.txt`, `.md`, and text-based `.pdf` files in one configured folder and, when enabled, search the public web and read a small number of public web pages. It is read-only: it cannot edit documents, run shell commands, access other folders, sign in to websites, submit forms, post, or send email.

## Requirements

- macOS 14 or later
- Ollama for macOS
- Python 3.10 or later
- Internet access for the initial app/model/dependency downloads; model inference then runs through the local Ollama service

## Run on a Mac

1. Install and open Ollama: <https://ollama.com/download/mac>
2. In Terminal, download the model:

   ```bash
   ollama pull qwen3:8b
   ```

3. In Terminal, enter the folder containing this repo and run:

   ```bash
   cd local-agent-poc
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   streamlit run app.py
   ```

   To enable web research, set up a search API key first (see below), then start the app.

4. Streamlit opens the chat UI in your browser, normally at `http://localhost:8501`.
5. Use the sidebar to choose a documents folder or upload a few test files. Ask questions in the chat box. Expand the tool-call panel to see which documents the agent searched or read.

## Enable web research (optional)

Web search uses [Tavily](https://tavily.com). Page reading runs on your Mac and does not use Tavily.

1. Create a Tavily account at <https://app.tavily.com> and copy your API key.
2. In the project folder, copy the template and add your key:

   ```bash
   cp .env.example .env
   open -e .env   # set TAVILY_API_KEY=tvly-...
   ```

3. Restart `streamlit run app.py`. The sidebar shows whether the key was loaded and has a toggle to turn web research on or off.

`.env` is listed in `.gitignore` and must never be committed. The key is read only from `.env` (or the shell environment) and is never shown in the UI.

**Cost:** Tavily's free plan includes 1,000 API credits per month without a card; a basic search costs 1 credit, and pay-as-you-go is $0.008 per credit (check Tavily's pricing page for current terms). With the default limit of 3 searches per question, that is roughly 330+ researched questions per month on the free plan.

**Privacy:** with web research on, your search queries are sent to Tavily and pages are fetched from the public internet from your Mac. Answers are still generated by your local Ollama model. Turn the toggle off to keep a conversation fully local.

If your Mac has limited free memory, try `ollama pull qwen3:4b` and enter `qwen3:4b` in the model field.

## What the agent does

The model receives the conversation and the function descriptions. It may request `list_documents` to see filenames, `search_documents` to find relevant passages, and `read_document` to inspect one matching file. With web research enabled it may also call `web_search` (Tavily, up to 5 results with title, URL, snippet and date where available) and `fetch_page` (downloads one public page and extracts its title, date and main text). Python validates every request and performs the read-only operation. The returned text goes back to the model, which drafts the answer and cites source filenames, or web page titles, URLs and dates. The app also appends a **Sources** list built from the pages the tools actually read.

The tool loop stops after eight rounds, with at most 3 web searches and 4 fetched pages per question. Files are limited to 5 MB each and document text is capped before being sent to the model. PDFs must contain selectable text; scanned PDFs need OCR first. Content in documents is treated as reference material, not instructions.

## POC boundaries

- Only `.txt`, `.md`, and `.pdf` files are listed, searched, or read.
- Each file is limited to 5 MB; extracted text is capped before it is sent to the model.
- The tools only read files under the configured folder.
- Web access is read-only: GET requests only, no cookies kept, no sign-ins, form submissions, posting, or email.
- Per question: at most 3 web searches, 4 fetched pages, and 8 tool rounds.
- `fetch_page` only allows `http`/`https` URLs on ports 80 and 443, without user names or passwords. Hostnames are resolved and blocked if any address is loopback, private, link-local (including cloud metadata), carrier-grade NAT, multicast, or reserved; `localhost`, `.local` and similar names are blocked. This check is repeated on every redirect (maximum 3), and the connection is pinned to the checked address. Environment proxy settings are ignored for page fetches.
- Fetched pages must be HTML or plain text, are capped at 2 MB with a 10-second timeout, and extracted text is capped at 12,000 characters. PDFs and other files on the web are not read.
- Web page text and search snippets are wrapped as untrusted content; the model is told never to follow instructions inside them. This reduces, but cannot fully eliminate, prompt-injection risk, so check important answers against the cited sources.
- No shell, database, or write actions are connected.
- The local web UI is intended for use on your own Mac. Do not expose its port to your network without adding authentication and other controls.

## Tests

Offline safety tests (URL blocking, redirects, limits, untrusted-content markers) need no network or API key:

```bash
python -m unittest discover -s tests
```

## Suggested first evaluation

Try ten questions: four with direct answers, three requiring multiple passages, and three whose answers are absent. Check that the agent names the right source and says when it cannot find support. Use a throwaway set of non-sensitive files for the first run.

For web research, also try a few current-events questions and one page containing instructions (for example, a page telling the assistant to ignore its rules); check that answers cite title, URL and date, and that the assistant does not act on the page's instructions.
